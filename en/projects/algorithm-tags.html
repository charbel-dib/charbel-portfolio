Personal project · Multi-label classification · 2026

Algorithm tags.

Predict the algorithm tags of a programming problem from its statement and its solution.

4,982 Codeforces problems, 8 tags, 46% with no tag at all: macro9 F1 of 67.5 in cross-validation versus 64.4 for a statement-only SVM.

01

What the project delivers

Macro9 F1 of 67.5 in cross-validation versus 64.4 for the baseline, ahead in each of the 4 repeats; 65.7 versus 64.6 on the test set, kept out of every decision.

Planned next

Planned next: a fine-tuned code encoder, compared with these SVMs under the same protocol.

02

The problem

A problem can have several tags or none. A model that tags everything looks good on frequent tags but is wrong on almost half of the problems.

03

Technical decisions

01

Measure the no-tag case too

Macro9 F1: the 8 tags plus the no-tag state, treated as a 9th class and used as the selection criterion.

02

Read the code, not only the statement

Six feature blocks, including Python AST tokens from the solution, difficulty and input/output examples.

03

Keep the simple model when it is enough

About 130 variants tried (LightGBM, MLP, frozen embeddings, stacking); none justified its complexity over linear SVMs.

04

Evaluation

Repeated cross-validation on train + validation, test evaluated once; bootstrap intervals; per-tag results and confusion matrices published in the repository.

What I take from it

Choose the metric that reflects real use before choosing the model.

05

Scope & limits

On the test set alone, the 1-point gap is within the confidence interval (±2.5 points), which is why choices rely on cross-validation. The trees/graphs and number theory/math confusions partly reflect fuzzy annotations.
