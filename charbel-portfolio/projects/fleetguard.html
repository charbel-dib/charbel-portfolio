01 / Le problème

Une panne manquée coûte plus qu’une fausse alerte.

Sur un jeu déséquilibré, un bon taux d’exactitude peut masquer les défaillances les plus coûteuses. Le défi Scania attribue un coût de 10 à une fausse alerte et de 500 à une panne APS manquée. C’est ce compromis qui doit guider la décision.

02 / Les choix techniques

01

Évaluer avant d’optimiser

Baselines explicites, partitions par groupes de doublons et séparation des rôles d’entraînement, de calibration et de choix du seuil.

02

Figer une décision complète

Le modèle, le prétraitement, la calibration et le seuil sont enregistrés ensemble. Le test officiel est évalué après ce gel.

03

Rendre le modèle utilisable

API FastAPI, revue de lots CSV et interface React. Les scores et les données manquantes restent visibles pour interpréter une décision.

03 / Ce que le projet produit

Sur les 16 000 observations du test officiel : 95,73 % de rappel, 43,05 % de précision, 16 défaillances APS manquées et 475 fausses alertes. Coût total : 12 750 unités du challenge. Ces résultats sont consignés dans la model card du dépôt.

Ce que j’en retiens

Relier une métrique ML à une décision opérationnelle, sans dissimuler le prix à payer en fausses alertes.

04 / Périmètre & limites

Classification sur un jeu public anonymisé, pas prévision d’une panne future. Les résultats ne valident pas un usage en flotte réelle. L’infrastructure AWS est préparée dans le dépôt ; un déploiement AWS effectif n’est pas établi par le rapport consulté.
